01 — The problem

A payment transaction isn't one request. It's a story.

A card authorization is really a sequence: an ISO 8583 0100 request, a 3-D Secure challenge, an issuer response, a completion. Every existing defense — rate limiter, WAF, fraud model, session guard — scores one message at a time. An attacker who understands this can split an attack into five pieces, each engineered to stay under its own detector's threshold, and hand each piece to a different layer. Every layer reports "clean." The attack still lands.

TIG-CDO's answer: build the graph of the whole sequence first (the Semantic Transaction Correlator, or STC), score how well it conforms to how a real transaction is supposed to unfold (the Transaction Coherence Score, or TCS), and use that score to amplify the five individual layer signals rather than average them in as a sixth. That's the whole mechanism. The console below is the actual formula — try to break it.

05 — The blueprint

Where all of this lives

Five components, one graph. Nothing here is a black box — every arrow is a real data path in the architecture.

STC builds the transaction graph from cross-layer events and computes TCS. CLCS fuses the five layer signals and amplifies them by TCS. BIM watches the baseline for the slow poisoning in Phase 2 and can force a rollback. PSRG throttles by transaction context, not IP. PADO turns the CLCS band into a graduated response — the same Green/Yellow/Orange/Red used in the console above.

07 — Terms used above

Glossary

TCS
Transaction Coherence Score — how well a sequence of events matches the protocol a real transaction is supposed to follow.
CLCS
Cross-Layer Composite Score — the five layer signals, amplified by TCS, into one number.
STC
Semantic Transaction Correlator — builds the transaction graph that TCS is computed from.
BIM
Baseline Integrity Monitor — a drift detector that catches slow poisoning of what "normal" looks like.
PSRG
Payment-Semantic Rate Governor — throttles by transaction context instead of per-IP.
PADO
Pre-Authorized Defense Orchestrator — turns a CLCS band into an actual response, instantly.
CSDA
Composite Slow-Degradation Attack — the threat model this paper is built around.
FDCE
Federated Declined-Card Exhaustion — a card-fraud reading of the same composite signature.
